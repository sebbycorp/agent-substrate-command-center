SOLO ENABLEMENT · SIMULATION · NOT A LIVE CLUSTER

Run harness agents on the Kubernetes you already have — instead of paying a cloud agent PaaS to host them somewhere else.

Harness agents are a new class of workload. Kubernetes was designed for long-lived stateless services. Agent Substrate is how kagent runs the new class on your existing platform.

1. The alternative path

AWS Bedrock AgentCore went GA in October 2025. Its SDK passed 2 million downloads within 5 months of preview. Google ADK — the framework under what became Gemini Enterprise Agent Platform (formerly Vertex AI Agent Builder / Agentspace) — passed 4.7 million downloads.

Those are SDK adoption proxies, not revenue or customer-count growth rates. Do not say “growth rate” unless you mean downloads. Do not say “Vertex” as the current product name.

2. Capacity already sitting there

Cast AI 2026 report: average CPU utilization 8% in 2025 (down from 10%); CPU overprovisioning 69% (up from 40%). Cast AI sells cluster optimization software — they have a reason to make waste look dramatic. Komodor found similar overprovisioning. Direction is likely right; the source is not neutral.

Accurate frame: the marginal compute cost of running agents on capacity you already pay for is close to zero. Substrate itself, possible GPU node pools, and ops overhead still cost money.

3. Anatomy — why agent-per-pod breaks

Stateless microserviceHarness agent
IdentityBound to the pod / service accountMust survive the process. Session ≠ pod.
ResourcesSized for steady loadBurst, then idle. A full pod reserved for nothing.
LifecycleOne long-lived process per podSpin up, work, checkpoint, maybe a new process next time
IdleStill the same process, still the same podShould leave the worker. Snapshot, not a resident process.
